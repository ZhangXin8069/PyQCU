## 2. 失败与根因证据

### 2.1 `bad object header version number` 是 **source**，不是 gauge

`[产物]` 5 个 `.err` 的 traceback（`logs/{327f9aa5,23daf98e,35548a2b,c9bfd6bf,c3bd73d2}.err`）全部停在：

```
File ".../pyqcu/testing/simple/kupl_multigrid.py", line 1366, in main
    source_local = _read_local_slab(
File ".../pyqcu/testing/simple/kupl_multigrid.py", line 1210, in _read_local_slab
    with h5py.File(path, "r", **open_kwargs) as handle:
OSError: Unable to open file (bad object header version number)
```

`[脚本]` 当前树行号语义逐条核对：

- 1366 = `source_local = _read_local_slab(...)`（**source** 读）；
- 1345 = `gauge_local = _read_local_slab(...)`（gauge 读，**在 source 之前**）；
- 1362 附近 `gauge_read_seconds = perf_counter() - input_read_started` 已执行 → gauge 已成功返回；
- 1210 = `_read_local_slab` 内部 `h5py.File(...)`；`_read_local_slab` 定义在 1177。

判据：32 个 rank **同一调用点、同一异常** → 文件侧资产损坏，不是 MPI/halo/几何/数值问题；只有个别 rank 异常才是并行/绑定问题。改并行参数或同命令重跑无意义。
