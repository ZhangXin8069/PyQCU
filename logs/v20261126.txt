2. 已核实：Legacy-MG 层级是递归，不是 gauge（§177）
   op(0) = 细层 odd-Schur Clover 算子；op(L) = R_L · op(L-1) · P_L。
   level 2 的算子是 level 1 33-stencil 的 Galerkin 投影。全树搜索
   coarse_gauge/block_average/coarsen_gauge/coarse_clover 只命中 QUDA 散文，
   没有实现，也不需要实现。Wilson-Clover 是 onsite + 1 hop，表达不了 33 点的
   2-hop 耦合 => 把 gauge + Clover 交给 applyMultigridBuildNullVectorsQcu /
   applyMultigridBuildStencilLocalQcu 必然失败，或者静默构建另一个算子。
   => level 2 的构建只能在 Python/torch（matvec 是参数）。读者入口：
   skills/pyqcu-solver/SKILL.md 的 2026-11-26 小节与
   skills/pyqcu-solver/references/mg-cache-comparison.md 的“深层 transition”。

3. 已核实：探针在原 stencil 父算子上有效（§177）
   合成父 stencil：max ||A2 v - R A1 P v||/||.|| = 4.89e-16（isotropic block 2,
   E=(2,2)）、4.26e-16（anisotropic (2,2,2,1), E=(3,3)）；A2·delta 的支撑恰好
   33 个 offset。原语：pyqcu/torch/tools/_multigrid.py:105-166
   （give_null_vecs）、:168-241（local_orthogonalize）、:873-953
   （_probe_point + build_stencil）、:1018（apply_stencil）；参考链
   pyqcu/cuda/_multi_gpu.py:84-160，:229 就是全部交接
   （S = lambda v: apply_stencil(hnn, hdg, sit, v)）。
   结论：归纳到任意深度成立，不需要新的物理输入。

4. 作废（void）：奇异输入上的所有收敛与基比较（§176）
   mass=-0.277 => kappa = 1/(2*(-0.277)+8) = 0.1343003，比自由 kappa_c = 1/8
   高 7.4%。单位 gauge（clover 项恒零）或 sigma=0.1 近单位 gauge 上，
   Wilson-Clover 在 cos p_x = 1/(2*kappa) - 3 = 0.723 处有精确/近零模，Schur
   补奇异：1000 次迭代后相对残差停在 7-12%，各 rank 逐位相同且有限。
   => 该输入上 BiCGStab 失败不说明求解器；null-vector 构建失败不说明 builder
   （同一个集体 builder 已在 32/16/128 rank PASS）；§173 的 overlap 0.115 与
   “legacy 多抓 6.1x”一并作废。收紧 --atol、换 seed 都无效，只能换热化 gauge。

     driver 的 params（params[13]），而串行路径 :1002 硬编码 1000。L48 配方的

     CCS_DRUN_RANK_FILE 指向它；设了以后 placement 由 rankfile 决定
     （-nn/-rpn/-R 只告警），但仍必须过资源校验：drun -R 的 cpu 值要与 dsub -R
     授予的每节点核数对得上（rpn × core ≤ 授予核数），否则 drun 直接拒绝，
     症状只是普通 rc=255（144 vs 72 那次见 remote-l48-experience §8.4）。
     只看报告 mpi_size/grid/local_lattice，不根据告警推断 rank 数。
   - prod(lattice_grid) == ranks：--grid 的乘积必须等于 comm 的 rank 数，否则
     parser 直接报错（kupl_multigrid.py:1330）。
   - drun 只在计算节点存在；单 rank 也用 drun -mpi pmix -nn 1 -rpn 1 --（§175）。
   - 不要给 launcher 接管道：> logs/full.out 2>&1 落文件，事后读文件再过滤
     （remote-l48-experience §8.6）。

10. KUPL Legacy-MG 端口到 CUDA 结构（代码 2026-11-25，文档 2026-11-26 同步）
    代码侧只读、本轮未改一行。`cpp/kupl/qcu/src/lattice_clover_multigrid.cpp` 删除了
    细层 BiCGStab 外层与周期粗修正，**只剩一条外层 = 右预条件 FGMRES(m = 10)**：
      外层      z_j = M^-1 v_j; w = A z_j; Arnoldi; x += Z y; restart 按真残差
      M^-1      nu_pre = 4 步 MR 平滑（作用在进来的向量上）-> restrict -> 一次
                coarse cycle -> prolong -> 权重 1 加回；**无 post-smoothing**
      粗层      cycle() = CUDA 的 V-cycle 体（2 步 BiCGStab 前平滑、restrict、递归、
                prolong、2 步后平滑）；**两级时入口层即最粗层，该体不运行**
      门        6 步窗口残差比的几何平均；连续两个窗口 >= 0.9 就把预条件子关到本次
                solve 结束，复现 CUDA 的 adaptive preconditioner gate
      dispatch  `_MG_USE_DEFLATE_ == 0` 或 `--mg-levels 1` = 没有粗空间，直接
                `set_.clover_bistabcg`
    被替换掉的东西（任何文档再把它写成现行机制都是错的）：
      - BiCGStab 修正器循环、`correction_interval` 调度、`KUPL_MG_CORRECTION_INTERVAL`
      - `smoothing_prefix` / `KUPL_MG_NU_PRE` 前缀
      - 解析最优阻尼 `t = <r,Ac>/||Ac||^2`（作为活机制）
      - `diagnose_correction` 与 `MG_CORRECTION_DIAG` 行（`best_damping` /
        `best_ratio` / `overlap` / `cos_overlap` / `capture_bound` /
        `reduction_bound` 的打印）
      - "无改善就关掉修正、回落 fine BiCGStab"
      - `KUPL_MG_OUTER` 开关；`MG_LEVEL_ITERS` 的 `fallback_fine=` token
      - `MG_LEVEL_ITERS` 仍打印 `level0/level1/...`、`total=` 与
        `accepted_corrections=`，后者现在计**预条件应用次数**，不再计"被接受的
        阻尼修正"

    差异都无法归因到硬件。端口后两后端结构一致，差异才有归属。
