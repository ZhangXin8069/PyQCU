### 1.0c 🔴 HIGH: `.pyi` stub 中 `argv` 默认大小错误

**文件**: `pyqcu/cuda/qcu/qcu.pyi:1`
**严重程度**: 🔴 严重

```python
# .pyi stub:
_argv: torch.Tensor = torch.Tensor([0.0]*define._SET_PTRS_SIZE_)  # size=100!

# cuda/define.py actual:
argv = torch.Tensor([0.0]*_ARGV_SIZE_)  # size=7
```

若调用方依赖 stub 的默认值（100 元素），C++ 后端将越界读取 `params[7..99]`，访问未初始化的内存。当前所有调用方显式传入 7 元素 tensor，所以暂未触发。

### 1.0d 🔴 HIGH: `.pyx` 中 multigrid 函数使用未 `cdef` 声明的指针变量

**文件**: `pyqcu/cuda/qcu/qcu.pyx:138-159`
**严重程度**: 🔴 严重 — 性能退化

```cython
# 模块级 cdef long long 变量 (lines 6-17):

# applyMultigridRestrictQcu (line 138):
```

`coarse_out`、`fine_in`、`null_vecs`、`fine_out`、`coarse_in`、`hopping`、`sitting` 等变量缺少 `cdef long long` 声明。Cython 将其视为 Python `int` 对象，每次 C 函数调用时插入类型转换。**影响**: multigrid CUDA 路径每次调用多出 ~8 次 Python↔C 类型转换。

### 1.1 🔴🔴 CRITICAL: Multigrid Cycle — BiCGStab 状态在粗网格修正后未重置

**文件**: `pyqcu/solver/_multigrid.py:384-409`
**严重程度**: 🔴🔴 致命 — 粗网格修正后收敛退化甚至发散

**问题**: 每当执行粗网格修正 (`count_restart > num_restart`) 时，残差 `r` 被重新计算：
```python
r = b - matvec(x)  # line 408
count_restart = 0  # line 409 — 但仅重置了计数器！
```

但下一次 BiCGStab 迭代使用的 `r_tilde` (投影影子向量)、`p`、`v`、`s`、`t`、`rho_prev`、`alpha`、`omega` 全部来自**修正前的迭代状态**。第351行 `rho = vdot(r_tilde, r)` 将旧 `r_tilde`（修正前指向的残差）与新 `r`（修正后的残差）做内积，结果无意义。

标准 BiCGStab 重启要求：
```
r_tilde = r.clone()           # 新影子向量
p, v, s, t = 0, 0, 0, 0      # 搜索方向重置
rho_prev = alpha = omega = 1  # 标量状态重置
```

**影响**: 多层级 MG 求解器在粗网格修正后每次都会偏离正确收敛路径。对于 ill-conditioned 系统，可能直接发散。

**修复**: 在第409行 `count_restart = 0` 之后添加完整的 BiCGStab 状态重置。

## 5. 🔴🔴 R2 修复引入的新 Bug

### 5.1 🔴🔴 CRITICAL: R2 NPU stout `f1` parity 修复仍然错误

**文件**: `pyqcu/smear/_stout.py:170`（R2 修复行）
**严重程度**: 🔴🔴 致命 — R2 修复引入了相反的 bug

R2 的"修复"写入：
```python
f1.real[parity] = -f1.real[parity]   # -re  ✓
f1.imag[parity] = -f1.imag[parity]   # "conj sign flip: -(-im) = +im" ← 注释错误！
```

但数学推导：
- 标准路径: `f1[parity] = -f1[parity].conj()`
- 若 `f1 = a + bi`: `conj() = a - bi`, `-conj() = -a + bi`
- 正确 NPU 实现应为: `f1.real = -a`, `f1.imag = +b`
- **R2 实际实现**: `f1.real = -a`, `f1.imag = -b` ← **错误！**

注释说 `+i` 但代码写 `-f1.imag`。正确的第170行应为:
```python
f1.imag[parity] = f1.imag[parity]  # 无负号：conj翻转 → leading minus翻转回来
```

**影响**: 当 `c0 < 0`（parity=True）时，NPU 路径的 f1 虚部符号与标准路径相反。R2 测试通过是因为大多数 gauge 配置下 `c0 >= 0`，parity 分支不执行。

### 5.2 🟡 Clover 项缺少 trace 移除

**文件**: `pyqcu/dslash/_clover.py:256`
**严重程度**: 🟡 中等

```python
F -= F.permute(1, 0, 2, 3, 4, 5).conj()  # F = Q - Q^dag
```

标准 QCD clover improvement 要求无迹反厄米部分：
```
F^TA = (Q - Q^dag) - (1/3) Tr(Q - Q^dag) * I
```

当前代码未移除 trace 部分。MILC、Chroma、QUDA 等主流 LQCD 代码全部移除 trace。

### 5.3 🟡 Clover 系数可能差 2 倍

**文件**: `pyqcu/dslash/_clover.py:112`
**严重程度**: 🟡 中等

```python
_clover_factor = -0.125 * _coeff  # = -kappa/(8*u_0)
```

以 `c_sw=1`、sigma = γ_μ γ_ν、F = Q - Q^dag 为标准推导给出 `-kappa/16` 而非 `-kappa/8`。代码的系数是标准推导的 2 倍。这可能被 5.2 的 trace 移除缺失部分抵消，但需与已知参考实现（QUDA/Chroma）交叉验证确认有效 `c_sw`。

### 5.4 🟢 Parity convention 不一致（3D vs 4D checkerboard）

**文件**: `pyqcu/tools/_define.py:164 vs :404`
**严重程度**: 🟢 轻微

`give_eo_mask` 使用 `x+y+z`（3D checkerboard）; `oooxyzt2poooxyzt` 使用 `x+y+z+t`（4D checkerboard）。t 方向 parity splitting 中两者可能不一致，需在实际运行中交叉验证。

## 6. 验证正确的关键项

深度分析确认以下实现数学上正确：

1. **Wilson dslash einsum 方程**: `Ccxyzt,scxyzt->sCxyzt` 正确 — C(颜色输出)映射到 sC
2. **Gamma 矩阵**: DeGrand-Rossi 手征基，`γ_μ γ_ν + γ_ν γ_μ = 2δ_{μν}I` 已验证
3. **Clover 场强**: 4 种 plaquette 取向正确，反对称提取正确
4. **BiCGStab 迭代顺序**: 完全符合 van der Vorst 1992 标准算法
5. **restrict/prolong**: `EeXxYyZzTt,eXxYyZzTt->EXYZT` 与 `EeXxYyZzTt,EXYZT->eXxYyZzTt` 正确
