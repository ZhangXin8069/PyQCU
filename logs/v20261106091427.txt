## 关键日志
### S1 - 基线、硬件上限与目标差距
- 目标: 在 Kunpeng 计算节点把 KUPL QCU-MG 的 24^3x64 c64 求解段压到约 0.1 s，并验证 HBM 实际利用。
- 最近有效计算节点基线: 0.434562751 s，16 iterations，PASS，独立真残差 3.5412238955e-6；32 ranks x 12 threads，grid 1 1 1 32。
- Roofline 模型: 当前约 149.5 GB/s、199.4 GFLOP/s；约为保守 HBM 上限的 2.8%-3.4%、FP32 SVE 理论峰值的 0.4%-0.5%。
- 0.1 s 模型需求: 约 650 GB/s 与 0.867 TFLOP/s，低于硬件上限；当前主瓶颈仍是 ht=1 scalar kernel、集合归约和同步，而不是 HBM 物理上限。
- 证据: data/kupl_roofline_20261106.json。

### S2 - E4 cache 摘要误判修复
- 根因: 原多维 Cartesian chunk 在拆分前导轴后按非连续 C-order 组合块，导致 manifest 的整数组摘要与流式摘要不一致。
- 修复: pyqcu/tools/_legacy_mg_cache.py 改为固定前缀坐标、仅拆分单一轴、保留完整尾轴，按严格 C-order 生成有界 chunk。
- 回归: pyqcu/testing/simple/mpi/test_mpi_contract.py 新增 blocked lonv 形状测试；本地直接回归 PASS。
- 远端 E4 cache 实测: lonv/hnn/hdg/sit 四个 manifest_eq_streaming 与 streaming_eq_whole 全部 true。
- E4 cache 路径: data/kupl_hbm_opt_20261106/mg_e4_tblock1_L24_v1/cache_E4_mg2x2x2x1.h5。

### S3 - true-MG fail-closed 与 coarse correction 诊断
- 新增 KUPL_REQUIRE_MG_CORRECTION=1：levels<=1/restart=0、fine-BiCG fallback、或成功结束但没有任何 accepted coarse correction 时直接失败。
- E4/L24 单 rank 因子扫描覆盖 0.001、0.01、0.1、1、10、100、1e4；coarse solve 均实际运行，首次 correction 把 fine residual 从 3723.37 降到约 3666.03，但后续全步长 correction 会增大 residual，随后被回退门拒绝。
- 结论: 之前把 fallback 结果记作 MG 的结论作废；当前 E4 coarse space 的全步长 additive correction 不足以稳定推进。
- 新候选: 在同一个 coarse solve 结果上做 damping line search，依次尝试 1、0.5、0.25、0.125，只接受使 fine true residual 下降的步长，避免重复 coarse solve。
- 远端 build-t2zblock-generic 已完成 C++ 重编译；一次编译错误已修正为 Complex<Real>(damping)，后续构建通过，但存在文件时间戳超前 0.6 s 的 clock-skew 警告。
