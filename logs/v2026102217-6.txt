## 关键日志
### S1 — 完成度比较
- 目标: 比较 C++ QCU Legacy MG 与 Strict-MG 的功能完成度和生产成熟度。
- 证据: Legacy 覆盖 33-tensor、fine-only、deflate、GCR/CA-GCR/BiCGStabL、mixed precision、CUDA/KUPL 和现有真实 LIME 生产路径。
- 证据: Strict 完整实现 full-coarse `X/Y/Yhat`、MATPC、递归 V-cycle 和 fused FGMRES，但当前只接受全层 `matpc/direct_pc`。
- 判断: 综合完成度 Legacy 最高；Strict 在 QUDA 语义保真和 tested cache-hit steady solve 上更强。

### S2 — 多卡能力
- 证据: CUDA Legacy 支持 MPI 多 rank 多卡，也支持 `MultiGpuMultigrid` 单 MPI rank 内多线程、一线程一卡。
- 证据: 当前 Strict MPI capability 全开；C++ strict 有 fine/coarse halo、全局归约和分布式 FGMRES，双 P100 一 rank 一卡实测收敛。
- 证据: Strict 没有对应的单进程多线程 `MultiGpuMultigrid` 驱动；单个 `CudaStrictMultigridSolver` 只管理一个 CUDA device。
- 证据: KUPL Legacy 与 Strict 都支持 MPI 多 rank 和 rank 内 OpenMP，测试覆盖 1/2/4 rank；KUPL 不使用 GPU 多卡。
- 判断: CUDA 两者都支持 MPI 多卡；Legacy 的并行形态和验证覆盖更广。Strict 的 MPI 多卡已实现并小规模验证，但缺少 Legacy 同等规模的真实 LIME/大格多卡生产证据。

结论：

- 综合功能覆盖和生产成熟度：Legacy MG 完成度最高。
- QUDA 风格语义保真度和 Strict 专用层级能力：Strict-MG 更强。
- CUDA Legacy 与 CUDA Strict 都支持 MPI 多进程、多 rank、一 rank 一卡的多卡并行。
- Legacy 还额外支持单 MPI rank 内多线程、一线程一卡；Strict 当前没有对应的官方多 GPU 线程驱动。
- KUPL Legacy/Strict 都支持 MPI 多 rank + OpenMP，但它们是 CPU 并行，不是 GPU 多卡。

完成度对比：

| 维度 | Legacy | Strict |
|---|---|---|
| 求解模式广度 | 更广 | 较窄 |
| 真实 LIME 生产验证 | 最成熟 | 已有 formal/小规模 MPI 验证 |
| CUDA 单进程多 GPU | 有官方驱动 | 无对应驱动 |
| MPI 多 rank 多卡 | 有 | 当前已实现 |
| QUDA full-coarse 语义 | 非严格对应 | 更完整 |
| cache 完整性 | 传统格式 | schema v2 更强 |

当前 Strict 的 `_strict_mpi.py` 已把所有分布式能力设为 true，C++ strict 也包含 fine/coarse halo、全局归约和分布式 FGMRES。双 P100 上的一 rank 一卡端到端 Strict solve 已收敛并通过独立真残差。因此旧文档中“Strict 仅单 rank”的结论已经过期。

但 Strict 的 MPI 多卡生产证据仍不如 Legacy 广，特别是大格、多节点、真实 LIME 和 c128 的长期性能数据仍需补齐。
