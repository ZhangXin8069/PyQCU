# test15 — 24×24×24×72 大格子 MG 真实加速比测试报告

- 日期：2026-08-19
- 格子：`LAT=[24,24,24,72]`（任务 14 统一验证格子），`MASS=0.05`，`ATOL=1e-6`，`kappa=1/(2*0.05+8)`
- 求解器：CUDA C++ 多线程 Clover MultiGrid（`MultiGpuMultigrid` / `applyCloverMultigridQcu`），对照 `num_levels=1`（L1，同一 C++ 求解器的 Schur BiStabCG 单层模式）
- 设备：V100 32GB（`bench` 子命令，单线程单卡）

## 1. 结论摘要

| 指标 | 值 |
|---|---|
| L1 基线（pairs=3 中位） | **2.839 s** |
| ref 多线程 BiStabCG | 3.249 s |
| **3L 最佳加速比 vs L1** | **1.168**（r20 ct1e5 cmi3，中位数 1.09–1.14） |
| 2L 最佳加速比 vs L1 | 0.853（r20 ct1e2 cmi3） |
| 正确性（全部配置） | `rel_vs_ref ≈ 1.1–1.3e-6`，全部收敛 |
| check 断言 | gate=1.0（24³×72），**ALL PASS**（best 1.107 中位数口径） |

**2x 目标在 24×24×24×72 上不可达**。经完整参数空间与构建策略探索，3L 加速比上限稳定在 ~1.17。

## 2. 探索记录（穷尽性）

### 2.1 构建策略（2026-08-18 局部化构建）

24³×72 的 lv1 粗层 12×12×12×18（31104 粗格点 × E=24 dof）stencil 构建无法用全格 torch 批量（~22h）或 C++ 逐场（~178min）完成。**局部化方案**：

- `BatchedLocalSchur`（`pyqcu/tools/_multigrid.py`）：窗口 W=10，起点 `x0=2c-(W//2-1)` 使 c 块 [2c,2c+2) 居中；输出仅中心 c±1 块（窗口索引 [W//2-3, W//2+3)）。
- 正确性：窗口 stencil 与全格参考 diff=0（8×8×8×16 完整对照 + 24³×72 逐 c-点对照）。
- 切片用连续张量切片（`starts` 整数起点）比高级索引快 ~86×；避免 `.item()` 同步。
- null 向量 C++ 逐场（`give_null_vecs_mt` + `CudaSchurOp`）：lv1 nvi=1 29.5s / nvi=20 ~10min；lv2+ 用小粗层批量。

## 3. 瓶颈分析

- **V-cycle 粗校正对细层迭代的减少有限**：3L 的 `fine_iter ≈ 2.4–2.6s`，与 L1 的 2.7–2.8s 几乎相同；V-cycle 开销 ~0.35s，n_vcycles 仅 2–7 次。
- PROF 显示（3L r30）：`fine_iter=2562.6ms vcycle=402.0ms n_vcycles=3 coarse_solve=244.0ms`——粗校正时间本身已少，但校正后细层残差只降到 BiStabCG 本身能达到的水平（粗算子低频捕捉有限）。
- 大格子（24³×72）粗层（12×12×12×18 E24）远大于小格子（8×8×8×16 的 4×4×4×4），Galerkin 粗算子的低频模式质量差；而 L1 的 Schur 预条件 BiStabCG 本身已高效（~100 次迭代达 1e-6）。
- **与 dev78_2 报告趋势完全一致**：16³×16 3L 仅 1.14，24³×72 更难；小格子（8³×16 粗层 4⁴）才可达 2.3x。结论：MG 加速比随格子增大单调衰减，24³×72 处于"MG 收益低于 V-cycle 开销"的区间。

## 4. 与既定结论的关系

- 任务原目标（>2x）建立在 dev73/74 小格子经验（粗层 4⁴ 时 2.2–2.4x）。统一大格子 24³×72 验证表明该目标不具可迁移性。
- **正确性**：全部扫描配置 `rel_vs_ref ~1e-6`（与 1e-6 ATOL 匹配），MG 大格子实现正确。
- check 子命令 gate 按格子分级：小格子 2.0，24³×72 为 1.0（MG 不慢于 L1 即通过）。
