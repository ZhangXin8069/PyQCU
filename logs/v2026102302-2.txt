按仓库正式对照口径（`c64`、两级、`block=2x2x2x2`、`nvec=12`，Legacy `dof=12`）：

| 路径 | cache 口径 | 数值 |
|---|---|---:|
| QCU Legacy-MG | 实际 33-tensor HDF5 cache | **1,560,678,400 B = 1.560678400 GB = 1.453495026 GiB** |
| QCU Strict-MG | schema-v2 逻辑 payload；该大格尚无实际 cache 文件 | **4,586,471,424 B = 4.586471424 GB = 4.271484375 GiB** |
| QUDA | 无同类持久粗算子 cache | **0 B / N/A** |

Strict 的 `4,586,471,424 B` 由 fine blocked `V` `2,038,431,744 B`、`Yhat` `2,038,431,744 B`、`X/X^-1` `509,607,936 B` 组成。实际 HDF5 文件会比逻辑 payload 略大，但当前 `24x24x24x64` Strict 记录失败/缺失，不能报实测文件大小。

QUDA 没有 QCU 这种持久 MG coarse cache。若把 `vec_load` 的 canonical null-vector bundle 也称为 cache：匹配的 nvec12 逻辑大小是 `1,019,215,872 B = 1.019215872 GB = 0.949218750 GiB`；历史完整 L24 QUDA MG 使用 nvec24，其 null basis 为 `2,038,431,744 B = 2.038431744 GB = 1.898437500 GiB`，但这不是粗算子缓存。

注意：仅凭 LIME 文件不能唯一确定 cache 大小；dtype、层数、block、nvec/coarse DOF 都会改变结果。以上数值对应仓库当前正式对照配置。
