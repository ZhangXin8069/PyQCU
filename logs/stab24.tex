\begin{abstract}
本报告对象为 \texttt{git tag dev73*} 共六个版本标签（\texttt{dev73}、\texttt{dev73\_1}、
\texttt{dev73\_2}、\texttt{dev73\_3}、\texttt{dev73\_4}、\texttt{dev73\_5}），
系统总结 CUDA-C++ Clover MultiGrid 求解器（\texttt{applyCloverMultigridQcu}）从
``正确但无性能优势''到\textbf{最高 $2.43\times$ 加速}的完整演进。报告基于
\texttt{logs/} 下的全部开发/调试/优化/结果报告与 \texttt{examples/qcu/} 下的全部
测试/基准/剖析脚本，给出\textbf{计算结果分析}（gauge 的 $SU(3)$ 性质、解误差、
null\_vecs 正确性、迭代次数）与\textbf{计算性能分析}（耗时、加速比、热点分解、
规模效应、参数扫描），并\textbf{以 dev73\_5 为范例对各版本做对照讨论}，讲明从
dev73 到 dev73\_5 的每一处改动、其原由与最终效果。

\vspace{1em}
\textbf{演进主线}：\texttt{dev73}（首个完整实现，正确性 $6.23\times10^{-7}$，加速比
仅 $0.87$--$1.28\times$）$\rightarrow$ \texttt{dev73\_2}（修 10 个根因 bug，level-0 改全算子，
正确但更慢 $0.15$--$0.41\times$）$\rightarrow$ \texttt{dev73\_3}（粗空间改基于 Schur 算子
$S$ 自身零模、粗算子 $A_c=P^\top S P$ 物化为 33 张量 stencil，主求解迭代 $\sim$90$\to$63--68、
减少约 30\%，但受 RTX 4060 内核启动延迟限制）$\rightarrow$ \texttt{dev73\_4}（定位 WSL2
同步开销 $\sim$177\,$\mu$s/次为根因，5 项同步极简优化，V100 上默认格子
$\{8,16,16,16\}$ 2 层中位数加速比 $1.26\times$、$8\times8\times8\times16$ 达 $2.07\times$）
$\rightarrow$ \texttt{dev73\_5}（建立干净测量协议并做精度/格子/参数扩展扫描，
$8\times8\times8\times16$ 复现 $2.43\times$（c64）/ $1.97\times$（c128），同时揭示
加速比随格子规模增大而\textbf{下降且非单调}的规模效应）。全系列解与参考 BiStabCG
一致（$vs\_ref\sim3\times10^{-7}$ c64 / $4\times10^{-8}$ c128）。
\end{abstract}

\section{方法与符号}
\label{sec:method}

\textbf{求解对象}：奇偶预条件（Schur 补）Clover 系统
\begin{equation}
  S\,x_{\_o}=b_{\_o},\qquad
  S=D_{oo}-\kappa^2\,H_{oe}\,D_{ee}^{-1}\,H_{eo},
\end{equation}
参考求解器 = \texttt{applyCloverBistabCgQcu}（奇偶预条件 BiStabCG，
\texttt{VERBOSE=0}）；MultiGrid = \texttt{applyCloverMultigridQcu}
（Schur 一致、多层粗层、33 张量粗算子、null\_vecs 缓存）。

\textbf{固定变量}（dev73\_4/dev73\_5）：mass=0.05、atol=$10^{-6}$、
gauge\_seed=42、$\kappa=1/(2\cdot0.05+8)\approx0.1235$、sigma=0.1、
null\_vecs 逆迭代 \texttt{nv\_iters=2}、E=48；默认格子 $\{8,16,16,16\}$（各向均不小于）。

\textbf{误差定义}：$vs\_ref=\Vert x_{mg}-x_{ref}\Vert/\Vert x_{ref}\Vert$
（MG 解与参考解相对差）；$mg\_res=\Vert b-D x_{mg}\Vert/\Vert b\Vert$（MG 全残差）。

\textbf{测量协议}（dev73\_5，干净测量）：每个配置在\textbf{独立进程}中完成；
参考 BiStabCG 与 MG \textbf{交叉计时}（ref, mg, ref, mg, \dots），各取 5 对的
\textbf{最小值与中位数}，最小化 GPU 时钟漂移影响。

\textbf{热点}：C++ 段计时 \texttt{PROF\_SECTIONS}
（\texttt{fine\_iter}/\texttt{vcycle}/\texttt{coarse\_solve}/\texttt{coarse\_dslash}）。

幺正性 $\max|U^\dagger U-I|$ 与 $\max|\det U-1|$ 在 c64 下单精度水平
（$\sim3\times10^{-7}$）、c128 下机器精度水平（$\sim10^{-16}$），
\texttt{check\_su3} 返回 \texttt{True}，满足 $SU(3)$（幺正性、$\det=1$、minor 恒等式）。

\subsection{解误差与全残差}
\label{sec:solution}

\begin{itemize}
  \item \textbf{dev73}（RTX 4060）：相对差 $\Vert x_{mg}-x_{ref}\Vert/\Vert x_{ref}\Vert
        = 6.23\times10^{-7}$，0 个 NaN，~104 次迭代收敛到 $5.7\times10^{-7}$；
  \item \textbf{dev73\_2}：全部配置（1/2/3 层、c64/c128、多格子多质量）收敛到与
        BiStabCG 相同的解，$vs\_ref\in[10^{-11},10^{-6}]$；c128 达 $3\times10^{-11}$；
  \item \textbf{dev73\_3}：$vs\_ref\approx3\sim4\times10^{-7}$（c64），
        33 张量粗算子与算子自由 $A_c$ 一致到 $2\times10^{-7}$；
  \item \textbf{dev73\_4 / dev73\_5}：$vs\_ref\approx3.2\times10^{-7}$（c64）/
        $2.4\times10^{-8}$（c128），与 v4 一致；MG 自身全残差
        $mg\_res\approx1.5\times10^{-7}$（c64）/ $6\times10^{-9}$（c128）。
\end{itemize}

\subsection{null\_vecs 正确性}
\label{sec:nullvec}

对照 \texttt{pyqcu/tools/\_multigrid.py}（逆迭代 + 块内 QR）做四重检查
（\texttt{mg\_v4\_verify\_nv.py}）：
\begin{itemize}
  \item \textbf{零模质量}：$\Vert S v\Vert/\Vert v\Vert\sim10^{-1}\sim10^0$，与 $S$
        最大本征值 $\sim1.2$ 同一量级或更小，证明 null\_vecs 捕获了 $S$ 的低模；
  \item \textbf{块内正交}：$\max|\langle v_i,v_j\rangle-\delta_{ij}|\sim3.6\times10^{-7}$
        （c64）/ $4.4\times10^{-16}$（c128），与机器精度一致；
  \item \textbf{restrict/prolong}：C++ 与 Python einsum 逐元素一致（相对差
        $\sim10^{-7}$，c64）/ $\sim10^{-15}$（c128）；
  \item \textbf{33 张量粗 dslash}：与 $A_c=P^\top S P$ 一致（相对差 $\sim10^{-7}$）。
\end{itemize}

\subsection{性能演进}
\label{sec:perf-evolution}

\textbf{dev73（基线）}：首个 C++ Clover MG 正确性达标（$6.23\times10^{-7}$），但
墙钟仅 $0.87$--$1.28\times$（随运行变化），求解时间 1742--3636\,ms（冷启动到稳定）。

\textbf{dev73\_2（修 bug + 全算子）}：10 个根因 bug 修复后各配置\textbf{数值全部正确}，
但 level-0 从奇偶预条件改为\textbf{全算子}，迭代数反升至 190--434，且小格子上 V-cycle
开销大于收益，墙钟 $0.15$--$0.41\times$。诚实结论：即使更优 null 向量也无法在该问题
规模（mass 0.05、中格子）上让 V-cycle 收益超过对 Krylov 空间的扰动。

\textbf{dev73\_3（Schur 一致）}：粗空间改基于 $S$ 自身零模后，迭代数显著下降
（$\sim$90$\to$63--68，$E{=}48,r{=}10$），主求解迭代数要求\textbf{首次满足}。
但墙钟仍慢（2L $0.170\times$、3L $0.186\times$）：RTX 4060 稳定在 210\,MHz 空闲频率，
内核启动延迟（$\sim$107\,$\mu$s/次）主导，MG 启动预算（细层 819 次 + 粗解 $\sim$2600 次
$\approx$ 3419 次）约为参考的 3 倍。粗解被确认为最大热点（dslash 仅 3\,ms，
dot+同步占 $\sim$416\,ms）。此阶段提出了融合粗解内核等优化方向，但当前硬件无法兑现。

\textbf{dev73\_4（同步根因 + 优化，V100）}：在 V100 上测得 WSL2 虚拟化
\texttt{cudaStreamSynchronize} 开销约 \textbf{177\,$\mu$s/次}——参考 BiStabCG 每迭代
20--30 次同步 $\Rightarrow$ 单次迭代约 6\,ms（计算 <5\%）。实施 5 项同步极简优化后：
\begin{itemize}
  \item 单进程 dslash 快速路径（去掉中间 ~9 次同步）：Schur dslash
        \textbf{4.5\,ms $\to$ 0.7\,ms}；
  \item Clover give 去冗余同步（$\sim$170\,$\mu$s $\times$ 2）；
  \item 同步极简细层 BiStabCG（\texttt{bistabcg\_iter\_fine\_fast}，点积直接写
        \texttt{device\_vals}，每迭代 1 次同步）：细迭代 \textbf{~6\,ms $\to$ ~2.6\,ms}；
  \item cooperative-groups 并行融合粗层求解（\texttt{multigrid\_coarse\_solve\_cg}，
        整个粗 BiStabCG 融合进一个 kernel，\texttt{grid.sync()} 跨 block 归约）：
        粗求解 \textbf{~30\,ms $\to$ ~10\,ms/次}；
  \item 参数扫描：ct=$10^5$（粗容差 $0.1\times\Vert r\Vert$，与 Python 参考一致）、
        粗层最大迭代 15、V-cycle 频率 $r=10\sim12$。
\end{itemize}
最终：默认格子 $\{8,16,16,16\}$ 2 层中位数加速比 \textbf{1.26$\times$}
（r=10 时 1.40$\times$），$8\times8\times8\times16$ 达 \textbf{2.07$\times$}
（c128 1.92$\times$）。加速比主要来自细层单迭代成本（$\sim$2.6--3.4\,ms vs 参考
$\sim$5.8\,ms，$\sim$0.6$\times$）与小格子上更少的迭代（65 vs 86）。

\textbf{dev73\_5（干净测量 + 扩展扫描，V100）}：建立独立进程 + ref/MG 交叉计时、
min of 5 对的干净测量协议后，沿精度/格子/求解器参数三条扫描轴给出完整对照（见
第~\ref{sec:dev735} 节）。$8\times8\times8\times16$ 复现 \textbf{2.43$\times$}
（c64）/ \textbf{1.97$\times$}（c128）；默认格子 2L 基准 \textbf{1.16$\times$}
（MG 399\,ms 与 v4 的 394\,ms 一致；参考本会话更快 464\,ms vs v4 的 549\,ms，
GPU 时钟所致）。

对 2 层配置，最粗层采用融合并行粗层求解（cooperative kernel），耗时计入 V-cycle，
故 \texttt{coarse\_solve}$\approx0$；对 3 层配置，中间层按逐迭代 BiStabCG 走
（\texttt{coarse\_solve} 非零）。dev73\_5 默认格子 c128 下 V-cycle 约 441\,ms、
占 MG 总耗时 69\%（双精度粗层求解开销主导）；$\{16,16,16,16\}$ 下 V-cycle 约
383\,ms、占 59\%。

\subsection{规模效应}
\label{sec:scale}

\input{dev73_5_tbl_lattice.tex}

加速比随格子增大而\textbf{下降且非单调}：
$8\times8\times8\times16$ 2.43$\times$ $\rightarrow$ 默认 $\{8,16,16,16\}$ 1.16$\times$
$\rightarrow$ $\{8,16,16,32\}$（t 方向放大）1.11$\times$ $\rightarrow$
$\{16,16,16,16\}$（x 方向放大）0.81$\times$。原因是单进程（WSL2）环境下粗层 V-cycle
修正的开销随格子规模增大而增长：$\{16,16,16,16\}$ 上 V-cycle 约 383\,ms 占 59\%，
且大格子上 V-cycle 修正并未显著减少细层迭代数（108 vs 参考 90），粗层开销大于收益；
$\{8,16,16,32\}$ 上细层迭代升至 119（参考 105），但单次细层迭代（$\sim$5.0\,ms）仍快于
参考（$\sim$6.3\,ms），故 MG 仍略优（1.11$\times$）。结论：MG 优势在\textbf{细层迭代
成本高于粗层修正成本}的配置（小格子、单精度）下最大。

\section{从 dev73 到 dev73\_5：改动、原由与最终效果}
\label{sec:evolution}

三条主线并行推进：\textbf{正确性}（bug 修复与算法一致化）、\textbf{性能}（同步开销
根因与同步极简优化）、\textbf{工程}（文档、脚本、缓存、测量协议、报告）。

\subsection{正确性主线}
\label{sec:ev-correct}

\begin{enumerate}
  \item \textbf{dev73：首个实现 + 大规模审查}。C++ Clover MG（953 行）一次成型，
        5 流并行、\texttt{device\_vals} 仅 GPU 写、\texttt{mpi\_real\_type<T>} 精度模板。
        三轮审查（135 项发现）修复 33 个 bug，其中 5 个致命
        （\texttt{lattice\_complex} 的 \texttt{operator*=}、\texttt{gauss\_gauge}
        越界写、CG 内存泄漏、grid dim 截断、\texttt{cuda} 包缺失）。
        \textbf{原由}：正确性是一切的前提；审查发现复数乘法、越界写等会被静默污染
        结果的缺陷。\textbf{最终效果}：$6.23\times10^{-7}$ 正确性达标，测试 8/8$\to$10/10$\to$13/13
        全通过。
  \item \textbf{dev73\_2：根因 bug + 全算子 level-0}。修 10 个根因 bug（索引转置、
        checkerboard 奇偶、缓冲覆盖、指针算术、网格尺寸、粗层 DOF、segfault、NaN）。
        \textbf{原由}：V-cycle 残差爆炸、3 层 NaN、coarse dslash 与 Python 差 97\%——
        需逐项定位。level-0 改全算子以匹配 Python 参考
        （\texttt{support\_parity=False}），并采用\textbf{受保护修正}（仅当修正确实
        降低残差才接受）保证 V-cycle 永不坏事。\textbf{最终效果}：全配置数值正确
        （$vs\_ref\in[10^{-11},10^{-6}]$），但性能退回 $0.15$--$0.41\times$——\textbf{为
        正确性付出的一次性代价}，同时获得关键认识：全算子 level-0 迭代数本就更差。
  \item \textbf{dev73\_3：Schur 一致粗空间}。\textbf{原由}：诊断发现粗空间基于\textbf{全
        算子 $D$} 的零模与 Schur 算子 $S$ 的低模\textbf{不匹配}，V-cycle 修正失效甚至
        反弹。\textbf{改动}：粗空间改基于 $S$ 自身零模（用 $S$ 的 matvec 逆迭代）；
        $A_c=P^\top S P$ 含对角耦合（实测 $|\text{on-site}|=0.77$、
        $|\text{nearest}|=0.79$、$|\text{diagonal}|=0.26$），故物化为 33 张量 stencil
        （on-site + 8 最近邻 + 24 对角），与算子自由版一致到 $2\times10^{-7}$。
        另修 breakdown guard 的 \texttt{rn} 初值 bug、粗层 $L_t$ 再减半、槽位偏移等。
        \textbf{最终效果}：迭代数 $\sim$90$\to$63--68（**减少约 30\%**），主求解算法
        ``迭代次数更少''的要求\textbf{首次满足}；但 RTX 4060 的启动延迟使墙钟仍慢。
  \item \textbf{dev73\_4：公平计时 + 同步修复}。修 4 个 bug：Cython 扩展过期、单进程
        强制 MPI halo、MG 以 \texttt{VERBOSE=1} 计时不公平、单 block 融合粗求解 NaN。
        \textbf{原由}：性能结论被不公平测量与同步开销污染。\textbf{最终效果}：正确性
        保持（$vs\_ref\sim3\times10^{-7}$），null\_vecs 缓存默认开启 + 四重正确性验证。
\end{enumerate}

\subsection{性能主线}
\label{sec:ev-perf}

\begin{enumerate}
  \item \textbf{根因定位（dev73\_4）}：独立微基准测得 WSL2 上
        \texttt{cudaStreamSynchronize} $\sim$177\,$\mu$s/次；参考 BiStabCG 每迭代
        20--30 次同步 $\Rightarrow$ $\sim$6\,ms/迭代（计算 <5\%）。MG 细层继承同结构，
        粗层另有每迭代 $\sim$14 次启动 + 1 次同步。\textbf{原由}：MG 的迭代优势被
        执行开销吞掉——问题不在算法而在\textbf{每次同步的虚拟化固定开销}。
  \item \textbf{5 项同步极简优化（dev73\_4）}：单进程 dslash 快速路径（Schur dslash
        $4.5\to0.7$\,ms）、Clover give 去冗余同步、同步极简细层 BiStabCG
        （细迭代 $\sim$6$\to$2.6\,ms）、cooperative-groups 融合粗解
        （$\sim$30$\to$10\,ms/次）、参数扫描（$ct=10^5, maxiter=15, r=10\sim12$）。
        \textbf{最终效果}：默认格子 2 层中位数 1.26$\times$、$8\times8\times8\times16$
        2.07$\times$（c128 1.92$\times$）——\textbf{从 $\le$0.19$\times$ 到 $\ge$1.2$\times$
        的关键一跃}。
  \item \textbf{测量协议（dev73\_5）}：独立进程 + ref/MG 交叉计时 + min of 5 对。
        \textbf{原由}：绝对耗时对 GPU 时钟敏感（同一配置参考 432--488\,ms vs v4 记录
        481--523\,ms），需排除噪声得出稳健结论。\textbf{最终效果}：加速比随格子增大而
        下降且非单调的\textbf{规模效应}被清晰揭示（2.43$\to$1.16$\to$1.11$\to$0.81$\times$），
        明确了 MG 当前单进程实现的最优适用窗口。
\end{enumerate}

\section{结论}
\label{sec:conclusion}

\begin{enumerate}
  \item \textbf{正确性}：dev73 系列六个版本最终全部与参考 BiStabCG 解一致
        （$vs\_ref\sim3\times10^{-7}$ c64 / $4\times10^{-8}$ c128）；gauge 满足 $SU(3)$；
        null\_vecs 四重检查全部通过。正确性演进路径：审查修 bug（dev73）$\to$ 全算子
        一致化（dev73\_2）$\to$ Schur 一致粗空间（dev73\_3）$\to$ 公平计时 + 缓存验证
        （dev73\_4）。
  \item \textbf{性能}：从 dev73 的 $0.87$--$1.28\times$（无优势）到 dev73\_5 的
        $8\times8\times8\times16$ 上 $2.43\times$、默认格子 $1.16\times$。关键一跃发生在
        dev73\_4——定位 WSL2 同步开销根因（$\sim$177\,$\mu$s/次）并做 5 项同步极简优化。
        dev73\_3 的 Schur 一致粗空间（迭代 $-30\%$）是必要前提，但只有消除执行开销
        后才转化为墙钟加速。
  \item \textbf{规模效应与适用窗口}：加速比随格子增大而下降且非单调
        （2.43$\to$1.16$\to$1.11$\to$0.81$\times$）；c128 在默认格子上 <1。MG 当前单进程
        实现的最优窗口是\textbf{小格子、单精度、细层迭代成本占主导}的配置。
  \item \textbf{测量与工程}：干净测量协议（独立进程 + 交叉计时 + min of 5）与
        脚本族/JSON/LaTeX 表格流水线保证了结论稳健、数字可复现；绝对耗时对 GPU 时钟
        敏感（$\pm$10\%），迭代数与解精度为稳健指标。
\end{enumerate}
