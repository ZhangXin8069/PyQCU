## 关键日志

### S1 — 根因：gauge patch 取自 rank 局部 slab
- 旧导出路径 `pyqcu/testing/simple/kupl_multigrid.py` 用
  `_periodic_window(gauge_local, patch_starts, patch_extent, ...)` 构造 patch。
- `gauge_local` 是本 rank 局部 slab；patch 在 x/y 上比局部盒大时，该函数把
  局部盒周期平铺，halo 拿到本 rank 自己的 gauge。实测 4-rank `8³×16`
  每个 rank 的 patch 有 `6144/8192 = 75.0%` 站点与真实全局 gauge 不同。
- 两次逐位实验闭合因果：
  - 实验 A（生产窗口）：与失败 cache `88816_r4_p0` 组装**逐位相同**，
    `lonv/hnn/hdg/sit` 全部 `max_abs=0.0`；
  - 实验 B（真实全局 gauge + 参考 lonv）：与 1-rank `88816_ref_p0`
    **逐位相同**，四项 `max_abs=0.0`。
- 因此 `hnn=0.493 / hdg=0.787 / sit=0.039` 全部由 gauge 窗口错误产生，
  与 C++ slot/halo 语义无关。

### S2 — 修复：CUDA-QCU patch 算法
- patch 每轴 `extent = local + 4*mg`（`halo=2*mg`）；
- `start = (coord*local - 2*mg) % global`；
- 若 `local + 4*mg > global` 且 `global % mg == 0`，退化为整轴（`start=0`）；
- patch 用 serial-local `1×1×1×1`（`node_rank=0,node_size=1`）调用
  单 rank builder，截 `coarse_center = 2*mg/step`（t 轴 `1`）的中心 block；
- patch gauge 来自全局 HDF5（`_hdf5_gauge_patch`）/全局数组/slab gather，
  禁止局部平铺；保持 `patch_galerkin=True`。

### S5 — t-only 在 patch 算法下不可用
- `grid 1 1 1 32` 时 x/y patch 因 `grid=1` 退化为整轴（24），t 也退化为整轴（64），
  每个 rank 构建整格（约 493 s），32 rank 并行仍 `rc=124`（≈355 s）。
- 同期**纯 BiCGStab 对照也超时**，证明不是 MG 数值问题。
- 多 rank MG 一律使用均衡 4D 分解（`2×2×2×4`、`4×2×2×2` 等）。

### S6 — MG 容差语义：1e-4 的“MG 0.128 s”不是 MG
- `coarse_atol = atol × coarse_tol_factor × 3^(levels−1)`，是乘不是除。
- `atol=1e-4` + 默认 `factor=1e4` → `coarse_atol=1.0`；粗层首行残差判据立即成立，
  解保持 0 → 修正恒 0 → damping 全回滚 → `fallback_to_fine=true`，最终纯 BiCGStab。
- 因此历史 `0.128289 s`（`restart=1, cmax=200, tol=1e5`）是 BiCGStab 回退，
  “MG 快 26.0%”作废。
- `atol=1e-6` + 默认 `factor=1e4` → `coarse_atol=1e-2`，MG 真正运行。
- cache identity 不含 `atol/coarse_tol_factor/cmax/restart/deflate`，设计正确。
