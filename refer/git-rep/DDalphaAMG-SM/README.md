# DDalphaAMG for the Schwinger Model

This project provides an MPI implementation of the DD$\alpha$AMG solver for the Schwinger model with Wilson discretization. The lattice is split across multiple MPI ranks, with each rank owning a subdomain of the 2D grid.

The solver combines:

- a Schwarz Alternating Procedure (SAP) as the smoother,
- test vectors to build the interpolation operator,
- GMRES as the coarse-grid solver,
- FGMRES as the outer solver,
- both V-cycle and K-cycle variants.

This code is intended for testing and benchmarking solver performance. It is not designed as a production-ready component for an HMC simulation workflow.

---

## 1. Build the code

From the project root, run:

```bash
mkdir -p build
cd build
cmake ../
make
```

This builds the executable generated by CMake. The lattice size is fixed in the CMake configuration file and must be adjusted there before building if you want a different volume.

The relevant configuration comes from [CMakeLists.txt](CMakeLists.txt).

---

## 2. Runtime parameters

The multigrid configuration is read from a file named `parameters` at runtime. The file format is:

```text
l, A_x, A_t, N_v, B_x, B_t
```

with the following meaning:

- `l`: level number, starting at 0
- `A_x`: number of aggregates in the x-direction across the whole lattice
- `A_t`: number of aggregates in the t-direction across the whole lattice
- `N_v`: number of test vectors used to coarsen the current level
- `B_x`: number of SAP blocks in the x-direction on a local rank
- `B_t`: number of SAP blocks in the t-direction on a local rank

The code expects one line per level. 

If the lattice has size $(N_x, N_t)$ and uses $r_x$ and $r_t$ MPI ranks in each direction, then each rank owns a local sublattice of size $(N_x/r_x, N_t/r_t)$. The aggregate count must satisfy:

- $A_i$ divisible by $r_i$
- each rank receives $A_i/r_i$ aggregates of size $N_i/A_i$ in direction $i$

For SAP blocks, the interpretation is slightly different. If the local domain is split into $D_i = N_i/r_i$ subdomains, then the block size is $D_i/B_i$ in direction $i$.

> In short: `A_i` controls the global aggregation structure, while `B_i` controls the local domain decomposition used by SAP.

---

## 3. Other solver options

Additional solver settings such as:

- number of pre-smoothing steps,
- number of post-smoothing steps,
- tolerance,
- GMRES length,
- and other numerical parameters,

are fixed at compile time and are defined in [src/variables.cpp](src/variables.cpp).

If you want to change these values, edit that file and rebuild the project.

---

## 4. Input and output data

The code inverts the Dirac matrix for a given gauge configuration and compares several methods. The methods to execute are selected in the main program, and any method not desired can be commented out in the appropriate source file.

### Required files

The solver expects:

1. a gauge configuration file,
2. a right-hand side (`rhs`) file,
3. a parameter file describing the multigrid setup.

Gauge configurations and RHS files must follow the format used by this [Schwinger model simulation](https://github.com/Fabian2598/SchwingerModel). The gauge configuration format and RHS format are identical in structure.

---

## 5. Runtime input sequence

When the program starts, it asks for the following values in order:

```text
mpi ranks on x
mpi ranks on t
number of levels
m0 (bare mass parameter)
path to the configuration file
path to the rhs file
path to the parameters file
```

The relevant solver information and metadata are written to output metadata files during execution.

## 6. Example configuration

A reference example is provided by [run_test.sh](run_test.sh). It sets up a test run for a $512^2$ lattice with:

- $\beta = 4$
- $m_0 = -0.1023$
- 16 MPI ranks total
- 2, 3, or 4 levels

The script also writes the `parameters` and `inputs` files that the solver reads at runtime.

### Example parameter structure

For a 4-level run, the parameter file can look like this:

```text
0 64 64 10 4 4
1 16 16 10 2 2
2 8 8 10 1 1
```

This corresponds to three levels with progressively coarser aggregate layouts, and the last entries specify the local SAP blocks per level.

### Example input sequence

The script writes runtime inputs in the form:

```text
4
4
4
-0.1023
2D_U1_Ns512_Nt512_b40000_m-01023_0.ctxt
rhs_conf0_512x512.rhs
parameters
```

## 7. How to run the provided test script

From the project root, execute:

```bash
./run_test.sh
```

This script:

- updates the lattice size in CMake if necessary,
- configures and builds the project,
- generates the executable,
- runs it with MPI using oversubscription via `mpirun --oversubscribe -n 16`.

You can change the values for:

- number of levels,
- lattice size,
- SAP blocks,
- Aggregates,
- number of test vectors,
- and other setup choices,

directly in the script before running it.
