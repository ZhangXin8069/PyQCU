\begin{abstract}
本报告使用 \code{git tag test27}（commit
\code{04382801c003353ecd1bc6b9bc10f6db750bf74d}）保存的原始
combined JSON、CSV 和 trace。66 个 combined 精确单元与 132 条 side
record 均未重新采样、未替换配置、未改动原始数据；派生表中所有数值与
2026-09-30 版逐字节一致。

2026-10-01 版只优化图表信息层级：图内标题不再显示 \code{kappa}，
面板标签不再重复显示 \code{mass}，轴标签不再附加线性轴说明；残差总览
标题也不再重复声明“仅残差使用对数轴”。测试元数据仍保留在固定协议表、
图内必要标题和正文口径中，确保图表既简洁又可追溯。

正式覆盖包括 1 cold / 2 warmup / 5 steady、配置哈希、输入 bundle、
公平性和独立 full-operator 真残差门。双 P100 的
$16\times32\times32\times48$ c64 请求仍按原记录使用 $16^4$ 容量替代。
\end{abstract}

\section{绝对耗时与时间比}

\begin{equation}
  R = \frac{t_{\mathrm{QUDA,steady}}}

\end{equation}

\code{median} 不是两个组中位秒数之商，因此时间比与绝对耗时可以独立核验。

\section{容量替代记录}

双 P100 的 $16\times32\times32\times48$ c64 请求项三次尝试均未同时
满足资源与时间门限：默认路径峰值约 15.9 GiB；
\code{PYQCU_MPI_OVERLAP=0} 约 14.8 GiB；extended CPU-staging
路径约 12.4 GiB，但 MG-2 setup 仍超过 570 s。该 6 个 combined 项
因此映射到已完整实测的 $16^4$ c64 对应项，并在
\path{capacity_substitutions.csv} 中显式标识。替代项只作为容量趋势证据，
不与原大格公平加速比混合。

\section{结论}

\begin{enumerate}
  \item 本版不改变 test27 的数值结论。66 个精确单元的全矩阵中位
        时间比为 1.0250，MG-2/3 合计 35/44 个单元优于 QUDA，
        BiCGStab 参考为 0/22。
  \item 图表标题已移除 kappa，面板标签已移除重复的 mass，轴标题不再
        附加线性轴说明；残差总览不再重复“仅残差使用对数轴”的提示。
  \item 66 个 combined 单元、132 条 side record 和全部派生表保持
        2026-09-30 版数值一致，源数据仍锁定在 test27 commit
        \code{0438280}。
  \item QUDA 最粗层残余项已显式取回。P100 c128 MG-3 的最粗层中位
        耗时为 PyQCU 14.781 s、QUDA 9.799 s；V100 c64 MG-3 为
        0.438 s 与 0.977 s。
  \item PyQCU/QUDA 最大真残差分别为 $7.40\times10^{-7}$ 与
        $7.97\times10^{-7}$，均通过 $5\times10^{-6}$ 门限；
        所有保留样本均低于 85\% 显存门限。
\end{enumerate}
