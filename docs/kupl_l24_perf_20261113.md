## 2. 节点、拓扑与绑定

性能样本取自 `cn19699` 与 `cn19650`。两者不是同一节点，跨节点数字只作量级
参考（第 7 节）。

| 项目 | 本次取值 |
|---|---|
| 节点 | `cn19699`、`cn19650` |
| 并行 | 32 rank × 12 thread（16 thread 用例见第 3 节） |
| MPI 映射 | `--map-by ppr:2:numa`、`--bind-to none` |
| `KUPL_NUMA_BIND` | `1` |
| `KUPL_MEMORY_POLICY` | `preferred` |
| `KUPL_MEMORY_NODE` | `local+16` |
| `KUPL_HUGEPAGE` | `1` |
| `KUPL_TOPOLOGY_REPORT` | `1` |
| 实测 `memory_node` | `16–31`（片上内存域） |

本次用 `preferred` 而非 `bind`：`KUPL_MEMORY_POLICY=bind` 配合
`KUPL_REQUIRE_MEMORY_BIND=1` 在 `cn19650` 上触发 rank 16 `SIGKILL`（RC=137），
改用 `preferred` 后正常（`logs/v202611130900.txt`）。HBM 硬绑定的失败边界
仍待单独复核。

MPI 部分实测为：

```bash
mpirun -np 32 --bind-to none --map-by ppr:2:numa --allow-run-as-root <program> ...
```

真残差恒为 `5.384866e-05`，说明样本差异只来自运行时抖动，不是收敛路径改变。
S11 的单点 `0.183044 s` 落在样本区间内，但比 5 次中位低 `1.74%`，不应继续
当作稳定中位引用。

真残差记录：`fast` 为 `5.384889e-05`、`t16` 为 `5.384853e-05`、`t18` 为 `5.384866e-05`、`prof4` 为
`5.38e-05` 量级；其余用例只记录 `PASS`，精确值待补。所有用例的迭代数均为 12。

派生比值有三点口径限制：

- `1.055×`（t2 vs base）与 `1.287×`（prof4 对 t2，即同一节点上的
  PASSIVE→ACTIVE）是跨批次派生值，不是同窗 A/B。
- 受控的 PASSIVE/ACTIVE A/B 只在 `cn19650` 完成，即 `1.28×`（第 6 节）。
- `1.099×` 来自 32r×16t 对 32r×12t，同时改变了 `-R cpu=16` 资源申请，
  不是纯线程数单变量实验。

## 4. 分项剖析

`KUPL_PROFILE_OPT=1`，ACTIVE，`cn19699`，rank 17：

| 项目 | 次数 | 时间 (s) | 字节 (MB) | 每 rank 带宽 | 聚合带宽 |
|---|---:|---:|---:|---:|---:|
| dslash | 52 | 0.104099 | 828.113 | 7.96 GB/s | 254.56 GB/s |
| clover | 52 | 0.013720 | 552.075 | 40.24 GB/s | 1287.63 GB/s |
| reduce | 51 | 0.023190 | — | 0.45 ms/次 | — |

phases：`prepare=0.003573 s`、`solve=0.156956 s`、`reconstruct=0.002327 s`；
solve 之外的 setup 约 `44 ms`（scratch/gauge halo）。

在 solve 阶段 `0.156956 s` 内，三项合计 `0.141009 s`（89.8%），算术占比为
dslash 66.3%、clover 8.7%、reduce 14.8%，其余为向量更新；本文不作进一步归因。

reduce 单次开销在 PASSIVE 下约 `1.02 ms`，ACTIVE 下约 `0.45 ms`（同一计时工具，
`cn19650` A/B 批次）。

`setup 约 44 ms + solve 0.156956 s = 0.201 s`，与同 lane 的
`wall_seconds=0.207077 s` 相差约 `6 ms`；差值归属（I/O、收尾与计时边界）未验证，
待补。

## 5. 带宽峰值与利用率

STREAM triad 探针：8M double × 3 数组，5 次取最优，12 线程/rank，
`--bind-to numa --map-by ppr:2:numa`：

| 指标 | 实测 |
|---|---|
| 每 rank | 18.3–20.1 GB/s |
| 聚合（32 rank） | 约 600 GB/s |

`logs/v202611130900.txt` 记录的探针点为 18.647 / 20.058 GB/s·rank；本文区间
18.3–20.1 GB/s·rank 取自本次各轮探针的运行范围，逐轮取值未在日志中列全，待补。

对照结论：

- dslash 的 7.96 GB/s·rank 约为探针峰值的 40–44%，属计算/latency 受限，
  不是达到带宽上限。
- clover 的 40.24 GB/s·rank 高于探针值，来自缓存复用；不能据此宣称超过硬件
  峰值，也不能把探针值当作 clover 的带宽分母。

## 6. 方法学：OMP_WAIT_POLICY

- 同节点、同 lane 仅切换 `OMP_WAIT_POLICY`：`cn19650` 由 PASSIVE
  `0.319600 s` 降至 ACTIVE `0.249223 s`，**1.28×**；两次均 12 it、`PASS`。
- 机制：ACTIVE 降低全局归约与向量更新等小并行区的线程唤醒开销；对应的
  reduce 单次开销由约 `1.02 ms` 降至约 `0.45 ms`。
- 该结论只由 `cn19650` 的一次同节点 A/B 支撑；每个分支各 1 个样本，
  多样本中位数待补。

## 7. 限制

- 节点间差异可达约 20%：同为 PASSIVE 基线，`cn19650` `0.319600 s` 对
  `cn19699` `0.266416 s`（1.20×）。两节点的硬件、负载与 `cpuset` 身份未逐项
  对齐，该比值只能作上界，不能当作纯节点性能差。
- 样本量：`t18` 已有 5 次重复统计（中位/min/max，第 3 节），其余用例仍为单样本。
- 当前最优中位 `0.186230 s` 仍高于 `0.1 s` 目标约 1.86×（样本最小值
  `0.180422 s` 约 1.80×）。
- `-ffast-math` 的约 1.4% 与 block-dslash 的 1.8% 均在噪声级，不构成加速，
  不作为默认构建或默认门控。
- 第 4 节剖析只有 rank 17 一份，ACTIVE 批次未逐 rank 核对分布。S8 剖析批次曾
  抽样 rank 26（dslash `0.1317 s`/52、clover `0.0200 s`、reduce `0.0523 s`/51、
  solve `0.2296 s`），该记录的 `OMP_WAIT_POLICY` 取值未标注；批次不同，
  不与第 4 节数字混比。
- `cn19650` 与 `cn19699` 的 PASSIVE 基线不是同一次提交的并排作业。
