## 2. 结论摘要

1. **18/18 节点当前频率均为 1.55 GHz，硬件上限均为 2.00 GHz，governor 均为
   `userspace`。** 本轮没有采样到 2.0 GHz 运行态的节点；“2.0 GHz 正常节点”
   是硬件能力，不是当前状态。
2. 18 个节点的拓扑完全一致：`nproc=592`、**16 个 CPU NUMA + 16 个无 CPU 的
   内存 NUMA**（`node16..31`）、每 CPU NUMA `cpulist` 宽 38（`node0=0-37`，
   …，`node15=570-607`）、内存约 **565 GiB**。
3. `userspace` governor 表示频率由外部策略设置，而不是内核
   `ondemand/schedutil`。**1.55 GHz 与 2.0 GHz 的差别是策略/功耗状态，
   不是节点型号**；用 `scaling_cur_freq` 单点采样即可区分，但必须与采样时刻
   和作业身份一起记录。
4. 若某节点确实运行在 2.0 GHz，CPU 受限路径的墙钟预期快
   `2.0/1.55 = 1.29×`（约 29%）；这是上界，不含内存带宽与通信不变的部分。
   跨节点比较必须先核对 `scaling_cur_freq`，否则 1.55/2.0 混用会把 29% 的
   频率差误判为代码或调度差异。
5. 16 个内存 NUMA（无 CPU）是片上内存域。sysfs 只给出节点编号，不给容量；
   容量与 `distance` 映射需另读 `node*/meminfo`、`distance`，本轮未采集。

## 4. 频率与性能的关系（可直接用于调优）

1. **判定规则**：`scaling_cur_freq / cpuinfo_max_freq`：
   - `≥0.98` → 视为 2.0 GHz 正常态；
   - `0.75–0.80`（1.55/2.0=0.775）→ 视为 1.55 GHz 低频态；
   - 其它值 → 记录原始 kHz，不归类。
2. **必记字段**：节点名、`scaling_cur_freq`、`cpuinfo_max_freq`、`governor`、
   采样时刻、作业号。缺少任一项的墙钟不得跨节点比较。
3. **同节点 A/B 前提**：同一节点内 A/B 不受频率差影响；跨节点 A/B 必须
   频率一致，或按 `1.29×` 做上界校正并标注为估计。
4. **用户态 governor**：`userspace` 下内核不会自动升频；若观察到 2.0 GHz，
   说明外部脚本/管理面显式设置了 `scaling_setspeed`。要稳定复现，应在作业内
   读取而不是假设。
